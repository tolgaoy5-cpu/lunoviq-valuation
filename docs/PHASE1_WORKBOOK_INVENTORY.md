## 2. Model architecture (same in all versions)

`00_Dashboard` (controls + outputs) → `01_Inputs_Historicals` (all inputs) → `02_Operating_Model` → `03_3_Statement_Model` → `04_DCF_Valuation` → `05_Sensitivity` → `06_Comparable_Valuation` → `07_Analysis_Scenarios`, plus `08_Data_Feed` (Lunoviq only).

- The model has 3 historical years (2023A–2025A, columns B–D) and 5 forecast years (2026E–2030E). Figures are in USD thousands.
- There are two revenue engines, selected in `00_Dashboard!B12`: `Unit Economics` (volume × price) and `Growth-Margin` (the one used for external data).
- **Pipeline entry points.** These cells are all in `01_Inputs_Historicals`:
  - Historical block: rows 18–34.
  - Forecast drivers: rows 38–55.
  - Valuation inputs: rows 59–67.
  - Scenario deltas: rows 72–75.
  - Financing: rows 80–88.
  - Growth-Margin drivers: rows 100–101.
- The Lunoviq template has 95 named ranges (`ctl_*`, `hist_*`, `drv_*`, `val_*`, `scn_*`, `fin_*`, `cap_*`, `gm_*`, `feed_*`). The WPS files have **none**.
- The health checks are in `00_Dashboard!I51:I57`. The overall status is in I57.
- The heaviest cross-sheet dependencies are:
  - 07→03: 260 references.
  - 02→01: 179 references.
  - 03→01: 124 references.
  - 05→04: 112 references.

## 3. How the versions differ (cell-level, shared formulas expanded)

The two derived versions branched from the base independently and **do not overlap**:

**Base → Lunoviq master** (53 cells + new sheet):
- A new `08_Data_Feed` sheet: raw SEC values, the tag used for each line, and 3 feed checks.
- New `03_3_Statement_Model` rows: 56 "Other Assets", 63 "Other Liabilities" and 69 "Other Equity". Each is fed from `08_Data_Feed` rows 32–34. The totals in rows 61, 67 and 72 were widened to include them, so that real-company balance sheets balance.
- `06_Comparable_Valuation!C68`: the formula changed from `=H60` to a computed precedent-transaction value.

**Base → `_Fixed`** (112 cells):
- `00_Dashboard` I37:L40: the Bear/Base/Bull columns now show the full model for the active scenario, and the Active column uses INDEX/MATCH.
- The "Forecasting Toolkit — FTE & Contractor Staffing" block was removed from `07_Analysis_Scenarios` (rows 134–156). `00_Dashboard!I56` no longer checks B155:B156, and nothing else referenced that block.

## 4. Findings and risks

1. **Master ambiguity (decision needed).** The pipeline uses the Lunoviq template, so the `_Fixed` dashboard improvements never reach the company models. Because the two change sets don't overlap, they can be merged mechanically.
2. **Company models have never been recalculated.** openpyxl writes formulas with empty cached values. In the KO model, every output (valuation, health checks, statements) is blank until the file is opened in Excel. The Lunoviq template has no cached values at all. Right now nothing validates the output automatically.
3. **openpyxl round-trip rewrites charts.** The template has 8 charts, and openpyxl re-serialises them on every save, which risks losing formatting. openpyxl also cannot open the WPS files at all.
4. **The pipeline overwrites formulas.** `edgar_feed.py` replaces `02_Operating_Model!B78:D78` (`=B76+B77`) with hard-coded COGS. This is intentional but not traceable.
5. **Forecast drivers are copied from history.** `edgar_feed.py` writes last-year growth, COGS margin, SG&A % and OpEx % straight into the forecast drivers. These are modelling assumptions; see step 3 of the script's own notes.
6. **Recalculation options on this Mac:** Microsoft Excel and `xlwings` 0.31.4 are installed. LibreOffice is not.
7. The code has no tests, no git repository, and all paths are hardcoded to the current directory. Code comments and output messages are in Turkish.
